# AES103 — Test/Bench File-Prefix Discipline

## What the rule checks

AES103 (rule code `AES103`, checker `TestFilePrefixChecker` in the `naming-rules` crate) enforces flat test/bench layout and legal prefixes:

- Files directly inside `tests/` must start with a legal test-type prefix: `contract_`, `unit_`, `integration_`, `dogfood_`, `smoke_`, `e2e_`, `acceptance_`.
- Files directly inside `benches/` must start with `bench_`.
- No subdirectories under `tests/` or `benches/` — the prefix IS the virtual folder.
- Files outside `tests/`/`benches/` are not subject to AES103.
- Barrel files (`mod.rs`, `__init__.py`, `index.ts`, `index.js`) are exempt.
- Support prefixes (`regression_`, `behavioral_`, `mock_`, `fixture_`) are legal in `tests/` but satisfy no AES704 category.

Three findings, checked in order:
1. File nested below `tests/` or `benches/` (flatten it up).
2. Stem starts with no legal prefix for its directory.
3. Stem starts with a prefix belonging to the *other* directory (bench file in `tests/`, or test file in `benches/`).

## Common violation causes

- Test file placed in a subdirectory of `tests/` (e.g. `tests/sub/unit_foo.rs`).
- Test file with no legal prefix (e.g. `tests/my_test.rs`).
- Bench file inside `tests/` (e.g. `tests/bench_foo.rs`), or test file inside `benches/` (e.g. `benches/unit_foo.rs`).
- File directly at scan root (outside both dirs) — not subject to AES103, no fix needed under this rule.

## How to fix (concrete steps)

1. Move the file up to `tests/` or `benches/` so it sits flat (remove nesting).
2. Rename it to `<type>_<subject>.<ext>` (tests) or `bench_<subject>.<ext>` (benches).
3. If the prefix belongs to the other directory, either move the file to that directory or rename it with the correct directory's prefix.
4. Re-run `lint-arwaky-cli scan .` and confirm AES103 no longer fires on that file.

## Example

Before (violates AES103 — nested + wrong prefix):
```
crates/calc/tests/sub/bench_calculator.rs
```

After:
```
crates/calc/benches/bench_calculator.rs
```

## Verify

```bash
lint-arwaky-cli scan .
# Confirm no AES103 finding remains.
# Fallback: confirm every file under tests/ starts with one of contract_/unit_/integration_/dogfood_/smoke_/e2e_/acceptance_ and every file under benches/ starts with bench_.
```
