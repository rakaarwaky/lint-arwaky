# AES101 — Naming Convention (Stem Shape)

## What the rule checks

AES101 (rule code `AES101`, checker `NamingConventionChecker` in the `naming-rules` crate) validates that each source file's stem matches the `prefix_concept_suffix` pattern:

- lowercase alphanumeric words
- separated by underscores (`_`)
- minimum word count (default 3, configurable via `config.naming.word_count`)
- every production source file must carry a recognized layer prefix: `taxonomy_`, `contract_`, `capabilities_`, `utility_`, `agent_`, `surface_`, `root_`

Barrel files (`mod.rs`, `__init__.py`, `index.ts`) and entry points are exempt. Files with no recognized layer prefix fail even if the stem shape otherwise matches.

## Common violation causes

- Stem uses camelCase or PascalCase instead of snake_case
- Stem uses hyphens instead of underscores
- Fewer than the configured minimum words (default 3)
- No recognized layer prefix (e.g. `user_checker.rs` instead of `capabilities_user_checker.rs`)
- Uppercase letters in the stem

## How to fix (concrete steps)

1. Identify the file's layer from its folder/role: `capabilities_`, `contract_`, `taxonomy_`, `utility_`, `agent_`, `surface_`, or `root_`.
2. Rename the file to `<layer>_<concept>_<suffix>.<ext>` using lowercase words separated by `_`, with at least the configured minimum word count.
3. If the file lives in a layer whose prefix doesn't match its role, move it to the correct layer folder instead of just renaming.
4. Update any imports/references to the renamed file across the codebase.
5. Re-run `lint-arwaky-cli scan .` and confirm AES101 no longer fires on that file.

## Example

Before (violates AES101 — no layer prefix, only 2 words, camelCase):
```
src/userDataChecker.py
```

After:
```
modules/my_module/src/capabilities_user_data_checker.py
```

## Verify

```bash
lint-arwaky-cli scan .
# Confirm no AES101 finding remains for the renamed file.
# Fallback compile gate: python -c "import <module>" / cargo check -p <crate> / npx tsc --noEmit
```
