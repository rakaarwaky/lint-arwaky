### Workflow (Sequential, No Skips)

**Step 1: IDENTIFY**
- Locate: `{{FEATURE_PATH}}/`

**Step 2: REFERENCE**
- Read `RULES_AES.md` Groups 1-5

**Step 3: FRD-ALIGNED PROTOCOL ANALYSIS (CRITICAL)**
Before ANY scalability/SRP analysis, you MUST do this:
1. Read `{{FRD_PATH}}` — count total FRs (Functional Requirements)
2. Count current protocol traits (capabilities layer) and aggregate traits (agent layer)
3. **Core Rules:**
   - **1 Feature = 1 aggregate trait** (agent layer) — one aggregate composes all protocol traits
   - **1 Feature = many FRs** — a feature crate has multiple FRs
   - **1 FR = 1 protocol trait** (capabilities layer) — each FR gets its own protocol
   - Methods per protocol are determined by what the FR needs — many methods is OK
   - **Method count is NEVER used as split criteria**
4. If protocol count ≈ FR count: **correct** — do NOT recommend split, even if a protocol has 29 methods
5. If protocol count << FR count: **undersized** — missing protocols (1 FR has no dedicated trait)
6. If protocol count >> FR count: **oversized** — too many traits for the number of FRs, consider merging
7. 1 aggregate per feature is ALWAYS correct — do NOT recommend splitting aggregates
8. **Exception: Surface layer** — surface traits follow different rules (thin wrappers, no FRD alignment needed)
9. **Exception: Foundation layers** (shared) — don't need their own aggregates, they re-export contracts from feature crates

**Example:**
- Feature with 4 FRs, code has 4 protocol traits (8/12/15/29 methods) + 1 aggregate → **CORRECT**, do NOT split
- Feature with 4 FRs, code has 1 protocol trait with 29 methods → **OVERSIZED**, split into 4 protocols aligned to 4 FRs
- Feature with 4 FRs, code has 2 protocol traits → **UNDERSIZED**, 2 FRs are missing dedicated protocols
